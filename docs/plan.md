# 分階段實作計畫

本計畫依完成條件推進，不承諾尚未估算的日期。第 0 階段以外的工作均尚未開始。

| 階段 | 工作 | 交付與完成條件 |
| --- | --- | --- |
| 0：起始骨架 | 建立 README、需求清單、決策紀錄、協作指南及通用設定 | 文件與目錄已提交；內部連結可用；沒有聲稱存在未實作功能 |
| 1：範圍確認 | 釐清 Q-01、Q-02、Q-06，及適用的資料問題 | 至少一個獲確認的使用情境、有界的第一版範圍與可驗證驗收條件；記錄確認來源 |
| 2：技術與資料契約 | 依已確認需求比較最小方案，處理 Q-03–Q-05、Q-07、Q-08 中的相關問題 | 紀錄技術決策、執行環境、適用的資料契約及授權；提供可重現的本機設定方式 |
| 3：最小完整實作 | 完成一個已確認情境的輸入到輸出流程，處理已確認的失敗情境 | 實作與測試可追溯至需求；更新安裝、執行與測試指令；由確認者依驗收條件檢視 |
| 4：交接與發布準備 | 整理已知限制、維護方式與適用的部署／回復流程 | 驗證乾淨環境可重現；明確記錄驗收結果；若需要發布，另確認目標環境與發布授權 |

## 推進規則

- 不因目錄已存在而引入框架、資料庫、外部服務或部署平台。
- 未確認的功能保留為提議，不直接實作。
- 只在技術與實際驗證需求確定後加入套件管理、鎖定檔與 CI。
- 測試應驗證已確認的行為與重要失敗情境，不以佔位測試宣稱產品可用。
- 第一版完成後，再根據使用回饋決定後續範圍。
